## Notes on Task 23 (admin console UI)

- **Tailwind had to be installed manually before `shadcn init` would run.** The brief assumed `shadcn@latest init` installs Tailwind itself ("this ... installs Tailwind at its latest version"); the current CLI (`4.20.1`) instead runs a preflight check and refuses ("No Tailwind CSS configuration found ... Install Tailwind CSS then try again") when there's no existing Tailwind setup in an *existing* Next.js project (it only bootstraps Tailwind for a brand-new `create` scaffold). Installed `tailwindcss@4.3.3` + `@tailwindcss/postcss@4.3.3` by hand, added `postcss.config.mjs` and a `src/app/globals.css` with `@import "tailwindcss";`, then re-ran `init`, which succeeded and rewrote `globals.css` with the full theme.
- **`shadcn init` is now interactive on component-library and preset choice**, with no all-in-one non-interactive flag beyond `-y` (which only skips the confirmation prompt, not the "Base UI / React Aria / Radix UI" and preset selectors). Used `-b radix -p nova`: **radix** because the brief's reference code uses Radix's `asChild` composition pattern throughout (`DialogTrigger asChild`, `SidebarMenuButton asChild`, etc.) rather than Base UI's `render` prop, so choosing Radix as the base keeps the reference code's composition pattern valid instead of requiring a wholesale rewrite to Base UI's API; **nova** because it's the CLI's own listed default (first option, "Recommended" is only shown for the base-library choice, not the preset — `nova` is simply first in the list and the plainest of the eight, no accent styling to fight).
- **The classic `Form` component (react-hook-form + zod) no longer exists as an install target in practice.** `pnpm dlx shadcn add form` reported `Checking registry ✔` and exited 0 having created and skipped nothing — no error, no file. The registry still lists a `form` item (`registry:ui`, depends on `radix-ui`, `@hookform/resolvers`, `zod`, `react-hook-form`), but it silently no-ops against this project's `radix-nova` style; searching the registry for `field` turns up exactly one item (`field`, `registry:ui`), and the shadcn skill's own bundled rules (`rules/forms.md`) confirm the replacement: *"Forms use `FieldGroup` + `Field`. Never use raw `div` with `space-y-*`..."*. None of this task's forms are React-Hook-Form-controlled (they're all plain `<form action={...}>` + `FormData`, exactly as the brief's own `accept-form.tsx` reference shows), so nothing was lost — `pnpm dlx shadcn add field` was used instead, and every hand-built form in this task (`accept-form.tsx`, `invite-user-dialog.tsx`, the resolution-queue manual-resolve dialog) composes `Field`/`FieldGroup`/`FieldLabel`/`FieldError`, not the brief's literal `<div className="space-y-4"><Label/><Input/></div>` markup.

## Version policy

No dependency version is pinned in this plan. Every install uses the latest published version
(`pnpm add <pkg>` / `pnpm add <pkg>@latest`), and the lockfile is the record of what was resolved.
Pinning an older version requires an explicit reason and the user's approval.
